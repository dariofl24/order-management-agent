# Demo de agentes — plan de implementación

**Goal:** implementar íntegramente el demo docente reproducible.
**Architecture:** CLI → Agent Loop → adaptador Ollama. Las decisiones pasan por Zod y un registro estático; el store controla reglas, confirmación e idempotencia.
**Tech Stack:** Node.js 22+, JavaScript ESM, ollama, zod, dotenv, node:test.
**Spec:** ../../../../Guia_Codex_Demo_Agentes_Ollama_Gemma3.md

## Restricciones

Solo gemma3:4b local. Sin frontend, servidor HTTP, servicios cloud, Docker ni base de datos. CONFIRMAR debe proceder del usuario. Datos en memoria y copias defensivas.

## Fases y verificación

- [x] 1. Estructura: package.json, entorno, scripts. npm install, npm run check, npm test.
- [x] 2. Store y tools: createStore(), cotizaciones, aprobación opaca ligada a operación exacta, createOrder(args, authorization). Pruebas de datos, límites, atomicidad e idempotencia antes de implementación.
- [x] 3. Contrato/adaptador: parseDecision(raw), decisionJsonSchema, createOllamaClient(config). Pruebas de JSON, timeout, configuración local y errores; el SDK no ejecuta herramientas.
- [x] 4. Loop: runAgent({userMessage,history,model,registry,store,approval,logger,maxSteps}). Pruebas de secuencias, inyección de nombres, argumentos inválidos, límite, repetición y errores.
- [x] 5. Confirmación/CLI: executeTool solicita approval.request(quote); solo CONFIRMAR autoriza. CLI con readline/promises e historial acotado. Pruebas de aprobación y sesión.
- [x] 6. Documentación: README, arquitectura, 10 escenarios, plan docente de 100 minutos, prueba live opcional. Verificación integral y revisión.

## Foco de revisión

Confirmación falsificada o reutilizada con otros argumentos; cotización desactualizada durante espera; nombres heredados del prototipo; JSON excesivo y timeout; EOF/SIGINT al pedir confirmación.

## Decisiones de ejecución

La guía es la especificación y el plan autorizados por el usuario. Se trabaja en el directorio solicitado, que inicialmente no es un repositorio Git. No se requieren commits ni worktree. Pruebas mock conforme a la guía, sin servicios externos.

## Registro de verificación

- Fases 1–2: instalación desde caché npm por restricción de DNS; check correcto, 11 pruebas aprobadas. Dependencias fijadas y lockfile reproducible mediante npm ci --offline.
- Fase 3: 27 pruebas aprobadas (incluye SDK con fetch simulado, schema y timeout).
- Fase 4: 41 pruebas aprobadas (loop, allowlist, límites y errores).
- Fase 5: 56 pruebas aprobadas (CLI y autorización exacta).
- Revisión independiente: detectó cache de lecturas obsoleta y Ctrl+C sin propagación. Se reprodujeron con 4 pruebas fallidas; corregido con invalidación selectiva y AbortSignal. Suite posterior: 60 pruebas aprobadas.
- Ollama real: con el comando autorizado npm test -- tests/ollama.live.js pasaron las dos pruebas live (stock/precio y compra con aprobación simulada); el comando directo test:live se omitió inicialmente por EPERM del entorno.
- Fase 6: README, escenarios, guía de 100 minutos, diagramas y pruebas live completados.
